# 设计说明与校准记录

## 1. 为什么只做六层

iOS 26 的液态玻璃，拆到可实现的粒度是七层。前六层都能在 iOS 16 上重建，第七层（边缘折射）不能。

做不出的原因不是工程量，是拿不到输入：

> `UIVisualEffectView` 的模糊由 WindowServer 在合成阶段完成。视图树里只有一层 `CABackdropLayer` 占位，它没有内容可读。要做折射，就得拿到「背后内容的像素」做位移采样——而这份像素不在我们手里。

试过的三条绕法都不通：

| 绕法 | 为什么不行 |
|---|---|
| 改写 `_UIBackdropViewLayer.filters` | 私有 filter 链只有模糊 / 色彩类，没有位移采样类 |
| 每帧 `drawViewHierarchyInRect:` 截图 | 拿到的是冻结帧，60fps 不可能；且截不到视频硬件叠加层 |
| 共享 `CABackdropLayer.groupName` | 跨图层组不可靠，未文档化，版本间行为不稳 |

所以本项目的定位从一开始就是「85% 的近似」，不是「复刻」。

## 2. 分工：哪一层负责什么

```
┌─ 顶边高光 ───────────────┐  ← 收益最大，纯公开 API
├─ 内壁暗环 ───────────────┤
├─ 染色 / 亮度叠加层 ──────┤
├─ 系统底色 ───────────────┤
├─ 背景模糊 ───────────────┤
└─ 连续圆角 squircle ──────┘  ← 零成本，与 iOS 26 逐像素一致
```

一条实测依据支撑这个排序：**玻璃的体积感有约 70% 来自边缘处理，不是模糊。**

在纯色背景上，只有模糊就已经很像玻璃了；一旦压到彩色视频上立刻露馅——因为缺少边缘那圈"光"。这也是为什么第 5 层优先于第 1、2 层。

## 3. 内容极性：为什么不读外观模式

常规做法是「深色模式用白字、浅色模式用黑字」。这个前提不成立：

- 首页在浅色模式下也是黑视频
- 消息页在深色模式下也可能是黑底

**模式说不清底色。**

所以判据改成：读宿主自己为内容设的文字色。它每页都重算，那就是"这一页底色是什么"的现成答案，而且是宿主自己保证读得清的答案。

```objc
// 宿主用黑系 → 它认为底色偏亮 → 我们也用黑系
polarity = DKGlassColorIsInk(hostColor) ? DKGlassPolarityLight : DKGlassPolarityDark;
```

三个配套细节：

1. **只取选中那颗按钮的文字色。** 未选中那颗可能是中灰或半透明，按明度分类会判错。
2. **过渡态样本要丢弃。** 切页过渡里宿主会把文字整体淡出，那一帧不能用来判极性。`alpha < 0.5` 直接跳过。
3. **未选中浓度取 60%。** 50% 只有约 3.9:1 的对比度（不达 WCAG AA），55% 卡在 4.68:1，60% 是 6.69 / 5.59。这个数字是有依据的，不要随手改成 0.5。

## 4. 为什么私有 API 默认关闭

`CAFilter` 可以给系统材质追加 `gaussianBlur` / `colorSaturate` / `colorBrightness`，理论上能再靠近一点 iOS 26 的饱和度。

但是：

- 私有 filter 名称跨 iOS 版本不稳定
- 在 16.3.1 上的实际可用性**本项目尚未验证**（开发环境没有真机）
- 一旦某个版本整条链不存在，可能出现材质消失或崩溃

所以默认路径完全不碰私有 API：亮度与染色用一层独立叠加视图实现（`_tintOverlay`），这已经能做到约 85%。`DKGlassInjectFilters` 是留给后续实验的开关，默认 `NO`。

打开之前请先读 §5 的校准方法。

## 5. 校准方法

**不要凭感觉调。** 找一台 iOS 26 设备并排比对，同一张壁纸、同一角度、同一亮度。

顺序很重要：

1. **先固定边缘装饰**（`DKGlassRimTopAlpha` / `DKGlassHairlineAlpha` / `DKGlassInnerShadowAlpha`）
   这是最确定的一层，初始值已接近参考。
2. **再调 `DKGlassBrightnessLift`**
   "玻璃亮起来"的主要来源。二分法：0.03 / 0.06 / 0.12 三档各截一张对比。
3. **最后才动 `DKGlassSaturationBoost`**
   需要先把 `DKGlassInjectFilters` 改成 `YES`。改了没效果就说明私有 filter 在这个系统上不存在，立刻改回 `NO`。

## 6. 性能注意

材质是逐帧路径上最容易出问题的地方。三条纪律：

1. **所有写入先比较。**
   在 `layoutSubviews` 里无谓地写 `frame` / `cornerRadius` 会让 CoreAnimation 反复提交事务，把触摸手势和选中状态冲掉。代码里每一处写入都有 `if (!CGRectEqualToRect(...))` 或 `fabs(...) > 0.01` 包着。

2. **不要逐帧重建材质。**
   换 `effect` 会把活着的材质换掉。原生 Regular 档切深浅色时只改 `overrideUserInterfaceStyle`，不重建。

3. **柔光斑不做玻璃。**
   触摸反馈的柔光斑用 `CAGradientLayer` 的径向渐变，不用 `UIGlassEffect`。几十个玻璃 effect 扛不住逐帧。

## 7. 与上游的差异

参考 [DYKiller](https://github.com/HierarchThurs/DYKiller) 时做的三个不同决策：

| 项 | DYKiller | 本项目 | 原因 |
|---|---|---|---|
| iOS 26 API 调用方式 | 编译期符号（需 26 SDK） | 运行时反射 | 用 16 SDK 也能编译，构建门槛低 |
| 私有滤镜 | 不用（直接走 `glassEffect`） | 可选增强，默认关 | 没有真机，不能默认赌私有 API |
| 底栏几何 | 反解系统 platter | 自己算 | 16 上没有 platter，反而更简单 |
